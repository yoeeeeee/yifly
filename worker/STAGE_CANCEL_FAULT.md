# Stage Cancel response-loss acceptance test

Default is DISABLED: migration creates an empty table; no secret, target or arm row is installed by deployment. No App change is needed for TestFlight 0.1.0 (130).

The three server-controlled gates are exact ECPAY_ENV=stage, exact ECPAY_STAGE_SIMULATE_CANCEL_RESPONSE_LOSS=true, and exact ECPAY_STAGE_FAULT_SUBSCRIPTION_ID matching the verified user's own subscription. An armed D1 row must match too. Client headers, query, JSON and supplied UID are never read by the hook. Production returns before any fault-table access.

Boundary: real CreditCardPeriodAction fetch → read complete response bytes → atomic conditional consumption of arm row → discard response → mark reconciliation_required. This runs before HTTP/result/MAC decisions, so even a provider failure becomes unknown. It does not assert provider cancellation. ExecStatus from the genuine existing QueryCreditCardPeriodInfo path determines the result afterward. Fault consumption is persistent and shared across isolates. Consumed rows never automatically rearm; a crash after consumption leaves the durable pending timeout safety path.

## ARM TEST — operator only; commands are NOT executed by implementation

Use the Worker directory and the disposable NEW test account, never the two protected existing subscriptions. First inspect:

```sh
npx wrangler d1 execute yifly-payment --remote --command "SELECT id,amount,status,cancel_at_period_end,cancel_state,created_at FROM subscriptions WHERE amount=190 ORDER BY created_at DESC LIMIT 10;"
```

Confirm ownership in your authenticated App's test account and (if necessary) the admin payment records. Latest timestamp alone does not establish ownership. The chosen record must be active, cancel_at_period_end=0, effective cancellation state none.

Set secrets interactively; do not put values in a command, source, chat or App:

```sh
npx wrangler secret put ECPAY_STAGE_FAULT_SUBSCRIPTION_ID
npx wrangler secret put ECPAY_STAGE_SIMULATE_CANCEL_RESPONSE_LOSS
```

Enter the disposable subscription ID at the first Terminal prompt; enter true at the second. Keep ECPAY_ENV stage. These alone do not arm a fault.

Replace REPLACE_WITH_NEW_TEST_SUBSCRIPTION_ID in this SQL with the verified disposable ID. IDs generated by the service are alphanumeric/underscore; do not interpolate untrusted arbitrary input. This writes ONLY fault infrastructure, never subscription data. Running again explicitly rearms the one-shot:

```sh
npx wrangler d1 execute yifly-payment --remote --command "INSERT INTO stage_fault_injections(fault_type,subscription_id,armed_at,consumed_at,consumed_request_id) SELECT 'cancel_response_loss',id,strftime('%Y-%m-%dT%H:%M:%fZ','now'),NULL,NULL FROM subscriptions WHERE id='REPLACE_WITH_NEW_TEST_SUBSCRIPTION_ID' AND status='active' AND amount=190 AND cancel_at_period_end=0 AND cancel_state='none' AND cancellation_request_id IS NULL ON CONFLICT(fault_type) DO UPDATE SET subscription_id=excluded.subscription_id,armed_at=excluded.armed_at,consumed_at=NULL,consumed_request_id=NULL;"
npx wrangler d1 execute yifly-payment --remote --command "SELECT fault_type,subscription_id,armed_at,consumed_at FROM stage_fault_injections;"
npx wrangler tail --format pretty
```

Require exactly the chosen armed row with consumed_at NULL before pressing Cancel. In TestFlight 130 stop renewal once. Expected log: STAGE TEST: cancel response-loss fault injected. App displays cancellation confirmation in progress. Inspect consumed_at and the test subscription using SELECT; require reconciliation_required, cancel_at_period_end=0, cancelled_at NULL and unchanged current_period_end. Press recheck: real QueryCreditCardPeriodInfo runs, normalized provider status is logged. Only cancelled produces confirmed and renewal stopped. Active returns none; unknown stays reconciliation_required. Retry must not send a second Cancel automatically.

## DISABLE after acceptance

```sh
npx wrangler secret put ECPAY_STAGE_SIMULATE_CANCEL_RESPONSE_LOSS
```

Enter false directly in Terminal. To remove all configuration instead, delete both Stage fault secrets with wrangler secret delete; this does not touch ECPay credentials. Keep the consumed D1 row as audit evidence. Production ignores all Stage fault configuration regardless.
